# 已知限制与后续建议

- **未用真实 DeepSeek Key 测试**；默认模型 `deepseek-flash` 依据 2026-10 官方文档，若调用报模型错误，在设置中改名即可。
- **Jina Reader**：开发机所在网络被 Jina 以「网络信誉差」拒绝匿名访问（HTTP 401）。手机网络下可能可用，也可能同样需要认证。为此设置里新增了可选的「Jina API Key」。开启后链接会经过 Jina 服务器。
- X、公众号等页面经常需要登录或靠脚本加载，本机抓取常常失败，需要靠 Jina 或粘贴原文。应用不绕过登录或反爬。
- URL 识别遇到中文字符就截止，所以路径里直接含中文（没有百分号编码）的 URL 会被截断。相对链接和网页中的链接按原样保存，不受这个影响。
- 顶栏和底栏的「毛玻璃」是半透明色块模拟的（Compose 不能直接模糊背后的内容）。
- 未实现：CSV/Markdown 导出、API Key 迁移、多提示词模板切换、链接可访问性验证（所有链接都标为未验证）。
- 没有开启 R8 混淆，APK 约 8 MB。
- 只在 API 34 模拟器（软件模式）上验证过，没有在真机上试过。
- **小红书相关（1.1.0）**：模拟器上没有安装小红书，「启动小红书」和「把封面图 ACTION_SEND 给小红书」这两条路径都没测过；只验证了未安装时退回系统分享面板。小红书是否接收外部分享的图片、接收后进入哪个页面，取决于小红书版本。应用不会自动发布。
- 剪贴板分三次写入，能否在输入法里看到三条，取决于输入法是否有剪贴板历史（如 Gboard、搜狗、讯飞都需要开启该功能）；没有历史的输入法只能粘贴最后一条（标签）。弹层里有「单独再复制：标题 / 正文 / 标签」作为补救。Android 13+ 每次写入系统都会弹一次「已复制」提示。
- 作者主页识别只看 URL 结构（x.com/<用户>、twitter、微博、公众号主页、知乎 people、B 站 space、YouTube @、小红书 user、Medium @、掘金 user、LinkedIn in 等），可能漏判少见的平台；GitHub 用户或组织主页（github.com/<名字>）不算作者主页，因为它往往就是资源所属组织。漏判的链接可以在链接清单里手动改成「来源」。
- 用户分享的主链接：内容平台上的帖子 / 文章一律归「来源」；GitHub 仓库、应用商店、文档页或非内容平台的网站首页归「资源」；其他网站的具体文章页也归「来源」。如果主链接其实就是工具官网的某个子页面，需要手动改成「资源」。
- 安全网的字样检查（原帖、作者主页、个人主页、@账号等）可能误报，比如工具本身叫「个人主页生成器」，只是提醒。
- 封面图用系统默认字体绘制，样式随系统字体略有差异；标题过长时自动缩小字号，最多 4 行，超出会以省略号结尾。
- 旧记录（1.0.0 生成）写在正文末尾的 #标签 不会自动移走，需要在结果页点「移到标签区」。
- 建议后续：真机走一遍完整验收；按需加入多套提示词模板、CSV/Markdown 导出、链接可访问性检查。
